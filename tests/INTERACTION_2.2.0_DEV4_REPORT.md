# 2.2.0-dev.4 快速重开编辑锁修复与回归记录

日期：2026-09-15。基线：本地 2.2.0-dev.3。本次保持本地开发，未安装、未提交或发布。

## 修复

- 页面正常离开且不进入浏览器往返缓存时，若当前页面仍持有编辑锁且锁距离过期超过 1 秒，通过 `sendBeacon` 排队释放；浏览器无法排队时回退到 `fetch(..., { keepalive: true })`。
- 卸载释放不再先等待一次读取锁文件，避免页面已经销毁、读取尚未完成、后续删除永远没有执行。
- 新页面发现有效外部锁时，在总计约 520 ms 的一次性宽限窗口内复查释放结果。旧页面已正常释放即可继续；锁仍存在则保持只读，不覆盖也不删除。
- 距离过期不足 1 秒时不做卸载期无条件删除，避免删除过期瞬间被其他页面合法接管的锁。
- `pagehide.persisted === true` 时保留锁，避免进入浏览器往返缓存的页面被当作真正关闭。

## 验证

- 自动测试：84/84 通过，包括 Beacon 排队、Beacon 失败后的 keepalive 回退、临近过期锁不删除。
- 独立 Chrome 交互回归：27 组通过；其中同一白板立即重开后可编辑，不再出现旧锁只读。
- 原有有效外部锁场景仍进入只读，点击重新获取编辑权后仅在外部锁释放时恢复，证明没有放宽互斥保护。
- 原有 24 组白板浏览器全功能回归通过，浏览器异常为 0。
- 类型检查、构建和安装包校验通过。

## 边界

- 浏览器或进程被操作系统强制终止时无法保证发送卸载请求，仍由 45 秒租约过期机制兜底。
- 网络极慢导致释放超过约 520 ms 时，新页面可能先短暂只读；释放到达后可使用“重新获取编辑权”，但不会冒险抢锁。
- 本轮未做真实 NAS 双设备断网测试；浏览器验证使用独立 Chrome 与内存模拟思源文件 API。
