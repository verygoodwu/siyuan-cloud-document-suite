# 思源 3.8.8 兼容性检查

检查日期：2026-10-21。依据官方稳定版 **v3.8.8** 的源码和发布说明，不以 master 分支推断稳定版行为。检查以集市 v2.3.2 为基线，修复随 v2.3.3 发布。

## 结论与处理

| 范围 | 检查结果 | 本地处理 |
| --- | --- | --- |
| PDF 导入 | v2.3.2 将 PDF 生成为浏览器 iframe，绕过思源批注阅读器 | PDF 单独拖入正文时交回思源；文档树和混合导入使用标准附件链接 |
| 数据库附件、只读区 | 原正文落点只查找 `.protyle-wysiwyg` 和块 ID，缺少数据库、嵌入查询和只读边界判断，可能抢走原生附件处理或绕过界面的只读行为 | 新增落点边界判断；覆盖 NodeAttributeView、数据库属性面板、查询嵌入、contenteditable=false、data-readonly 和 inert；文档树识别限定在实际文件树内 |
| 远程内核 PDF 导出 | 官方 Electron 主进程对远程内核的 `siyuan-export-newwindow` 和 `siyuan-export-pdf` 直接返回；插件原先仅按是否存在 Electron 决定导出路径，可能出现点击后无响应 | 使用 `kernelConnection` 检查连接模式；远程内核打开浏览器打印预览。本地和旧版连接保留既有流程 |
| PDF 标题分页 | 3.8.8 新增指定 H1–H6 标题另起页，插件原设置未覆盖 | 通过 `Protyle.applyExportHeadingPageBreaks` 能力检测显示选项，预览和导出共用宿主规则；关闭分页或旧版缺少能力时隐藏/禁用 |
| 开发 SDK | 原 siyuan 1.2.4，官方 plugin-sample 当前使用 1.2.8 | 同步到 1.2.8 并通过类型检查；仅开发依赖，不加入运行时安装包 |
| 被移除的 API | 3.8.8 移除 Protyle.updateTransaction | 插件未调用，无需迁移 |
| 保存与文件接口 | getFile、putFile、asset/upload、createDocWithMd、insertBlock、属性和导出接口在 v3.8.8 路由中仍存在 | 保留现有逐字节校验、编辑租约、恢复与冲突保护；接口存在不等于已在实机穷尽验证 |
| 菜单与紧凑模式 | 官方菜单已监听内容变化并更新布局；插件通过读取实际编辑区 padding 适配 iframe 宽度 | 暂不加入额外菜单高度补丁；保留创建/导出菜单提升失败后的标准插件子菜单入口 |

## 后续可做的优化

- 评估官方 `before-upload-assets` 上传事件，减少全局拖放监听的覆盖面。需要兼顾旧版宿主、混合导入和文档树创建，不能只替换一个监听函数。
- 思源 3.8.8 新增稳定选区插入接口 `insertContent`。当前插件有意按落点块追加预览；未来若改为光标位置插入，应在上传前保存目标，并处理关闭文档、只读及选区失效。
- 菜单提升仍依赖宿主 DOM 结构；紧凑模式、小窗口、多个菜单和特殊主题应列入实机回归。
- 官方脑图的新连线样式属于宿主脑图；插件 `.mm` 使用独立 MindElixir 页面，未发现需要随宿主一起升级引擎的证据。

## 验证与边界

- 94 项自动测试通过，包含 PDF 拖放传递、混合导入去重，以及本地/远程/旧版/浏览器 PDF 导出分支。
- 隔离 Chrome 回归通过：真实 DOM 的数据库和只读落点判断、标题分页能力检测和开关、原有表格/文本/脑图/白板交互；捕获的浏览器异常为 0。
- 新 SDK 类型检查通过。生产构建与安装包校验见本次交付结果。
- 浏览器回归使用模拟内核与宿主能力；未在实际 SiYuan 3.8.8、Electron 44.9.0、真实远程 NAS、macOS/Linux、移动端完成整套操作。因此结论是源码核对及自动回归通过，不是所有平台的实机认证。
- 最低版本声明仍为 3.7.4；新标题分页使用能力检测，不强制旧版调用新能力。本次未重新完成最低版本实机回归。
- 本地 v2.3.3 尚未发布集市，也未自动替换用户现有文档中的旧 PDF iframe。
