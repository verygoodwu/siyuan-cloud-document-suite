# 云文档套件发布到思源集市

本仓库已经列入思源集市。更新现有插件时，发布新的 GitHub Release 即可；不需要每次再向 Bazaar 提交 PR。发布脚本通过 GitHub API 提交源码并创建 `v*` 标签，仓库的 `.github/workflows/release.yml` 随后运行测试、构建，并把单个 `package.zip` 附到 Release。集市读取新的版本和安装包。

## 一次性准备

在本机安装 Node.js 24、pnpm 11、Git 和 GitHub CLI。先完成一次 GitHub CLI 登录并配置 Git 凭据：

```powershell
gh auth login -h github.com --web
gh auth status
gh api repos/verygoodwu/siyuan-cloud-document-suite/git/ref/heads/main --jq .object.sha
```

`gh` 使用本机凭据存储，不需要把 token 放入源码。先在允许联网的终端核验认证，受限环境中的网络失败可能被误报为 token 无效。API 检查成功后即可发布，即使 Git 无法连接 `github.com`。脚本只调用 GitHub API，不依赖 Git 远程推送，也不会退回网页逐文件上传。

## 每次发布

1. 确认本地包含远程的全部源码改动，在本地完成并提交代码。脚本发布当前提交中的文件，工作区必须干净。
2. 同时更新 `plugin.json`、`package.json` 的版本号；在 `RELEASE_NOTES_CURRENT.md` 写本次公告，并更新 `RELEASE_NOTES.md` 与 README 中的版本摘要。
3. 读取并核对远程 `main` 提交，再运行发布命令：

```powershell
$releaseHead = gh api repos/verygoodwu/siyuan-cloud-document-suite/git/ref/heads/main --jq .object.sha
pwsh -File scripts/release.ps1 -Version 2.3.3 -ExpectedRemoteHead $releaseHead
```

脚本会检查版本、公告、Git 状态和远端标签，运行自动测试、浏览器回归、类型检查与构建，校验 `package.zip` 后通过 API 上传变更、更新 `main` 并创建标签。远程提交发生变化时会停止；远程有本地缺少的文件时也会停止，避免遗漏源码。GitHub Actions 自动生成 Release 和正式安装包；脚本等待 `package.zip` 可见。只想先验证本地包时使用 `-VerifyOnly`，不会发布：

```powershell
pwsh -File scripts/release.ps1 -Version 2.3.3 -VerifyOnly
```

若标签已创建而 Actions 失败，先查看仓库 Actions 日志并修复，不要重复创建同名标签。集市通常在 GitHub Release 出现后异步刷新；思源客户端可能需要稍后刷新或重启。

## 安装包内容

`scripts/build.mjs` 生成主程序，`scripts/package.mjs` 将主程序、脑图/表格/白板等编辑器页面、图标、清单和更新记录打成**一个** `package.zip`。仓库里的 `static/mm-editor.js` 等文件是插件源码，不是独立插件。只上传版本号和公告而不提交这些源码，会让 GitHub Actions 从旧代码构建安装包。
